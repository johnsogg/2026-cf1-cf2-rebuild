# Objects

In programming languages, an object is a structure that groups data together.
You could have an object representing a person, so you'd need things like their
first name, last name, home address, social security number, job title, date of
birth, favorite music, ... whatever you need! Objects are a powerful way to
design with code.

## Object literals

In JavaScript, an object is defined with curlies, and lets you define as many
'properties' as you like, separated by commas. Each property has a name, then a
colon, then a value.

JavaScript objects are an extremely common way to write out complex information.
In fact, the internet essentially runs on what we call _JavaScript Object
Notation_, or _JSON_. JSON is a stricter format that is based on the JavaScript
object syntax.

<Callout intent="note">
  **JSON**: When your browser gets data from a server, there's a good chance
  that information is traveling over the network in this format. It is even
  useful for writing files. So even if JavaScript ends up not being your jam,
  JSON is so ubiquitous that you'll use it elsewhere. From within Javascript,
  you can convert just about any data to JSON by using `JSON.stringify(mydata)`,
  which will write `mydata` in this stricter JSON format for writing to disk or
  sharing over a network. Then, to read that strict JSON data, use `JSON.parse`.
</Callout>

Below is an example of a more complex JS object. I want to draw attention to two
aspects about this code. First, the data here has multiple layers to it: objects
can contain objects (or lists, or any other data).

Second, some of the property names are enclosed in quotes. This is because
property names don't have to obey the JavaScript rules for variable names.
Property names can start with numbers, include spaces or other punctuation, and
so on. To be safe you _can_ use double quotes around all property names, not
just the ones that aren't valid JS identifiers (many auto-formatters do this for
you). In this case, `id` and `firstName` and others are unquoted because they
don't need to be. `"street number"` is enclosed in quotes because the space
character is not allowed in an identifier. `"street"` is in quotes because I'm
being consistent - some of the other property names are in quotes, and it
aesthetically looks weird to me to see a mix of quoted and non-quoted property
names for the same object. This is entirely a matter of taste.

## Defining objects

If you need to record something like "how many times the user clicked", you only
need a single number. But if you want to record something that is more complex,
like the position and heading of an object in motion, there's more work
involved. Until now, you might have needed to do something like this:

```js
let xPosition = 50
let yPosition = 100
let xDelta = 5
let yDelta = -3
```

These variables are all independent from one another, even though we intend to
_use_ them as a team. And if you have more than one such item, you'd need to do
something unclean like `item3xPosition = 23` or whatever. Soon, your code is a
mess, and coming up with new names for things becomes a burden.

Using objects, recording an object's position and heading becomes something like
this:

```js
const ball = {
  x: 50,
  y: 100,
  dx: 5,
  dy: -3,
}
```

In the common case where you have several similar items, now you only need to
make `ball1`, `ball2` and so on. The property names are still just `x`, `y`,
etc. Much easier - we only have to come up with names for the top-level things
that are meaningful to us as programmers:

```js
const ball1 = {
  x: 50,
  y: 100,
  dx: 5,
  dy: -3,
}
const ball2 = {
  x: 20,
  y: 200,
  dx: 0,
  dy: 8,
}
```

Now, `ball1` and `ball2` are the two variables, and all the position and heading
data is _inside_ those structures. Much cleaner to reason about and program
with!

## Reading and writing objects with dot notation

If we already have `ball1` and `ball2` from above, we can read and write
property values like this:

```js
// read values
if (ball1.x < ball2.x) {
  // ball 1 is to the left of ball 2
}
// write values
ball1.dx = 3
ball2.dx = 4
// read and write values on the same line
ball1.x = ball1.x + ball1.dx
```

This is called _dot notation_. `ball1.dx` means "reach into the `ball1` object,
and use the `dx` property."

## Objects in action

Enough talk - let's take a look at how objects are used.

```p5sketch autoplay width=400 height=300
let particle1, particle2, particle3
let paused = false

function setup() {
  createCanvas(400, 300)
  textAlign(CENTER)
  particle1 = newParticle(random(width), random(height))
  particle2 = newParticle(random(width), random(height))
  particle3 = newParticle(random(width), random(height))
}

function newParticle(x, y) {
  const angle = random(TWO_PI)
  const speed = random(0.5, 1.5)
  return {
    x: x,
    y: y,
    dx: cos(angle) * speed,
    dy: sin(angle) * speed,
    color: color(random(255), random(255), random(255)),
    diameter: random(20, 50),
  }
}

function draw() {
  background("black")

  if (!paused) {
    moveParticle(particle1)
    moveParticle(particle2)
    moveParticle(particle3)
  }

  drawParticle(particle1)
  drawParticle(particle2)
  drawParticle(particle3)

  if (
    !paused &&
    isOffscreen(particle1) &&
    isOffscreen(particle2) &&
    isOffscreen(particle3)
  ) {
    particle1 = newParticle(
      width / 2 + random(-20, 20),
      height / 2 + random(-20, 20),
    )
    particle2 = newParticle(
      width / 2 + random(-20, 20),
      height / 2 + random(-20, 20),
    )
    particle3 = newParticle(
      width / 2 + random(-20, 20),
      height / 2 + random(-20, 20),
    )
  }

  noStroke()
  fill("gray")
  text("click to pause", width / 2, height - 10)
}

function mousePressed() {
  paused = !paused
}

function moveParticle(particle) {
  particle.x += particle.dx
  particle.y += particle.dy
}

function drawParticle(particle) {
  noStroke()
  fill(particle.color)
  circle(particle.x, particle.y, particle.diameter)
}

function isOffscreen(particle) {
  const r = particle.diameter / 2
  return (
    particle.x + r < 0 ||
    particle.x - r > width ||
    particle.y + r < 0 ||
    particle.y - r > height
  )
}
```

In this example, we've got three particles with different positions, headings,
colors, and sizes. Each of these particles is an object, and they have the same
_shape_ (they use the same properties), so we can treat them as different
instances of the same kind of thing.

Because we can treat them all the same, we can write functions like
`drawParticle` or `moveParticle` that take a single input - the particle
object - rather than six independent values for position, heading, and all that.
There are fewer moving parts, because all those parts are bundled together and
move as a group.

```p5exercise autorun size="medium"
let planet1, planet2, planet3

function setup() {
  createCanvas(300, 300)
  planet1 = newPlanet(80, 80, 1, "#6ec6ff")
  planet2 = newPlanet(120, 60, 0.6, "#ff8a65")
  planet3 = newPlanet(140, 40, 0.4, "#ce93d8")
}

function newPlanet(rx, ry, speed, planetColor) {
  return {
    rx: rx,
    ry: ry,
    speed: speed,
    color: planetColor,
    diameter: 20,
  }
}

function draw() {
  background("black")

  const cx = width / 2
  const cy = height / 2

  // star: fixed at the center
  fill("#ffd51a")
  circle(cx, cy, 50)

  const t = millis() / 1000

  drawPlanet(planet1, cx, cy, t)
  drawPlanet(planet2, cx, cy, t)
  drawPlanet(planet3, cx, cy, t)
}

function drawPlanet(planet, cx, cy, t) {
  const angle = t * planet.speed
  const x = cx + planet.rx * cos(angle)
  const y = cy + planet.ry * sin(angle)
  fill(planet.color)
  circle(x, y, planet.diameter)
}
```
