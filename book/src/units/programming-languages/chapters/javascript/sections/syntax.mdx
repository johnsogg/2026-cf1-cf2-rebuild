# Javascript Syntax

We've talked about language, we've talked about programming languages, but we so
far we've kept it abstract. In this section we'll talk about the specifics of
_Javascript's syntax_.

A programming language's syntax is defined as one big whole, but this is too
much for a new programmer to understand in one glance. So in this section we
will build up the syntax in pieces. We can examine little pieces of the big
picture by taking a view of little parts, like how you'd assign values to
variables, or how to make a new function definition.

From this perspective, I like the analogy of _anatomy_. A syntactical structure
has certain parts that make it unique - keywords and punctuation and the order
they are written. So in this section and elsewhere I will use _anatomy_ as a
metaphor to describe how correct code is written. Let's start with assignment.

## Anatomy: Assignment

Here is the syntax of an **assignment operation**. Use the nav buttons to
progress through the panes.

This is an example of an _expression_. There are lots of different kinds of
expressions - there are expressions for doing arithmetic, calling functions
(we'll see this soon), and just about everything else the language lets you say.
An expression is just a passage of code that can evaluate to something. In this
case, the expression `foo = 'hello'` evaluates to the value `'hello'`.

Many expressions have a certain order for doing things, and the above sequence
follows that order. When you write a line of code, JavaScript scans it for clues
about what it should do with it. In this case, it sees

```
<thing-on-left> <equals-sign> <thing-on-right>
```

... which matches the syntax for an assignment expression.

**Equals sign.** The `=` character is doing a lot of work here. Now that JS
knows this is an assignment, it has to do something with the left and right
sides.

{/* prettier-ignore-start */}

**Expression.** The next step is to _evaluate_ the right hand side. It always
does this before it does anything with the left hand side. In this case, the
right hand side is simply `'hello'`, which is also known as a 
<Term>string</Term>&nbsp;<Term>literal</Term>. We'll soon see that the
right-hand side can be complicated, but it always resolves down to a single value.

{/* prettier-ignore-end */}

**Variable.** The last step in an assignment is to identify the variable that
the value will be assigned into. In this case, it is a variable named `foo`. We
haven't looked at any other kinds of landing spots yet, but they exist (e.g.
object properties, list elements). After this assignment operation, the variable
`foo` contains the value `"hello"`.

## Anatomy: Mutable Variable Declaration

We just saw how we can assign to an existing variable. But where do they come
from? You need to _declare_ them first with a name. If you want to make a
variable that can change over time, you don't need to give it an initial value.
Here's how you'd do that.

## Anatomy - Function Definition

We've just covered the anatomy of declaring and setting variables, but we've
also seen _functions_ so I thought it would be good to take a look at how those
are defined and used as well.

A function is like a request. It has a name, and you can give detailed
instructions on what is to be done. It might have side effects. And when it is
done, it can hand you back some data.

Recall this from earlier:

```p5exercise autoplay width=150 height=150
function setup() {
  createCanvas(150, 150)
}

function draw() {
  background("black")
  fill("#888")
  circle(75, 75, 45)
}
```

The `function setup` and `function draw` parts are involved with defining
functions (called `setup` and `draw` respectively). We're also _using_ functions
by _invoking_ them: `createCanvas(150, 150)` is one example.

First, here's the anatomy of a function definition for code that greets somebody
by name, and says something different based on the time of day. I'm leaving out

## Anatomy - Function Calls

Now that we've defined a function, how can we use it? You can say we _call_ the
function, _use_ the function, _invoke_ the function, _execute_ the function, ...
I am probably forgetting other words as well. We have a lot of synonyms for this
because we do it all the time, probably because we talk about it so much.

Calling a function just involves naming it, and then putting the arguments
inside parentheses. That's it:

One thing that sometimes surprises people who are new to this is that the
parentheses really are needed, even if there's nothing inside them. There's a
meaningful difference between `sayHello()` and `sayHello` (without parens). The
version with parentheses will actually call the function; the second version
without parens simply references the `sayHello` function, without invoking it.

This comes back to the language's dependence on grammar to help it understand
what your code should do. Unlike other humans or an AI, the Javascript
environment won't try to make sense of statements that aren't grammatically
correct.

This chapter on syntax was a blast, wasn't it? No?

To recap, a programming language's <Term>syntax</Term> gives you a bunch of
rules on how the code must be written. You still have essentially infinite
freedom to be creative within those rules, but they are rules nonetheless.

This will be a recurring topic throughout the rest of the book. Like spoken
language, this is something you'll pick up as you progress, until you get to a
point where you write the code correctly based on intuition.
