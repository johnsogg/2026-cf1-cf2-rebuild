# Lists (aka Arrays)

So far when we've needed to make more than one item in some logical set, we've
written code with variables like `tempA, tempB, tempC` or `ball1, ball2, ball3`.
In this section we're going to cover lists of data that give us first class
language support for creating sequences of arbitrary length, without the need to
awkwardly name things `1`, `2`, etc.

Given the two approaches below, which would you rather use?

```js
// fixed number of named variables
const tempA = 48
const tempB = 51
const tempC = 47

// the same data, collected as a sequential list
const temperatures = [48, 51, 47]
```

In JavaScript the formal name for this is `Array` - so if you look on the web
for documentation (like the
[Array docs on Mozilla Developer Network](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array)),
that's the term you should use.

Throughout this text I will likely use the terms 'List' and 'Array'
interchangeably. This is a common but inexact convention. 'List' is a generic
term that just means 'sequence of data', while 'Array' means the specific data
structure in use (here, a JavaScript Array). Just keep it in mind as you work
your way through the book.

## Array syntax

A JavaScript array uses square brackets to delimit a comma-separated list of
values. These values can be anything - a list can contain numbers, text,
objects, or even other lists.

## Array literals

We already saw this in the intro:

```js
const temperatures = [48, 51, 47]
```

That creates a list of numbers. There happen to be three of them, but it could
have three thousand. Or it could be empty. Here's an empty array:

```js
const todoList = []
```

Arrays can have the same kind of thing in them (like our `temperatures` list),
and they also let you put a mix of things in there. Mixing types is
syntactically valid, but if you're doing that, you _might_ consider redesigning
your approach. When all of a list's items are of the same kind, you can rely on
that to easily do work on each item.

## Array access & length

We can access an individual item from a list using square brackets and a number:

```js
const firstValue = temperatures[0]
```

An index refers to the _distance from the beginning_ - so here we're accessing
the first item. The second item is (probably confusingly) indexed with `1`, the
third item is indexed with `2`, and so on. This is baffling to new coders, but
as long as you think of the index as meaning the _offset from the start_, it
makes more sense.

In JavaScript, our arrays are "smart" objects that give you additional
abilities. For example you can use the `length` property to see how many values
it contains:

```jsconsole size="small"
const temperatures = [48, 51, 47]
console.log("Item 0:", temperatures[0])
console.log("Item 1:", temperatures[1])
console.log("Item 2:", temperatures[2])
console.log("Length of the temperature list:", temperatures.length)
console.log("The last item is:", temperatures[temperatures.length - 1])
```

That final line shows how to get the _last_ item in an array. It is terse, but
`myList[myList.length - 1]` works. I'll soon show another way to do it with
`at`.

## Using lists in loops

Marching through lists is extremely common. You can use indices and `.length`
with a traditional for-loop to process each element:

```js
for (let i = 0; i < myData.length; i++) {
  const d = myData[i]
  // now do something with item i (in variable d) from myData
}
```

That approach has been in JavaScript since the very first version in the 90s.
But recently we've gained other approaches to iterate over a list. The `for-of`
approach maps nicely to what you often want, but without involving a counter or
index:

```js
for (const d of myData) {
  // do something with variable d from myData
}
```

## Array methods

A JavaScript array has a lot of additional behaviors attached to them, in the
form of methods that you can invoke. This is just a quick survey to give a
cursory sense of what is possible. Check out the
[MDN documentation](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array)
for more.

### [`push`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array/push) and [`pop`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array/pop)

You can add something to the end of a list with `push`, and remove the last
thing in the list with `pop`. This lets you add/remove to a list without needing
to be concerned with indices.

```jsconsole size="medium"
const todos = [] // empty to start with
console.log("At beginning, my todo list is:", todos)
todos.push("Mow lawn")
console.log("After adding one item it is now:", todos)
todos.push("Do laundry")
todos.push("Get groceries")
todos.push("Make dinner")
console.log("After adding three more, it is now:", todos)
todos.pop()
console.log("After removing the last item it is:", todos)
todos.pop()
todos.pop()
console.log("Then I popped two more, giving:", todos)
```

### [`filter`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array/filter)

If you have a list and want to trim it down in some way, you can use the
`filter` method. This takes a _callback function_, and until you've used these
for a while they can seem like dark magic. A callback is just a function that
you pass around as an argument to another function, and it can use that callback
to do some custom work.

Filtering is a good example of this. Say we want to filter a list of numbers, so
we only have those that are less than some `target` value. You'd do this:

```jsconsole size="small"
const target = 100
const data = [59, 104, 84, 100, 106, 102, 66]
const lessThanTarget = data.filter(t => t < target)
console.log("I started with:", data)
console.log("And my threshold target is:", target)
console.log("My filtered data is:", lessThanTarget)
```

The callback we passed in is the function expression `t => t < target`. This is
a function that takes a parameter `t`, and returns the expression `t < target`,
which is a boolean. The `filter` method uses this callback with every value in
the array, and the callback yields `true` if the value should be included in the
resulting filtered list, or `false` if the value should be omitted.

The `filter` function doesn't modify the original list - it just gives you a new
list.

To make this hit a little closer to our p5 home: you could use it to create a
filtered list of items that are still on screen, and store the updated list in
place:

```js
items = items.filter((item) => isOnScreen(item))
```

### [`map`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array/map) to create a new 1:1 list

Use the `map` method when you want to create a new thing based on every item in
a source list. For example, say we've got an array of circles and we want to
make an array of squares at the same location. You could use `map` with a
callback function that takes a circle and gives a square:

```js
const squares = circles.map((c) => ({
  left: c.x - c.r,
  top: c.y - c.r,
  side: c.r * 2,
}))
```

The resulting list `squares` has a one-to-one mapping to each circle in the
source list.

### [`forEach`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array/forEach) as an alternative to for-loops

Earlier I showed the vanilla for-loop and the newer `for..of` syntax. The
`forEach` method is yet another way to iterate over a list that uses callbacks:

```js
// just print out the value of each item
myData.forEach((d) => console.log(d))
```

### [`at`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array/at) for array access

We already saw how we could use square brackets to index into a list. You can
also use `at`, which supports negative numbers. This is interpreted as 'distance
from the end'. So earlier when we used `myData[myData.length - 1]` to reference
the last item, we could also use `at`:

```jsconsole size="small"
const temperatures = [48, 51, 47]
const last = temperatures.at(-1)
console.log("My list is:", temperatures)
console.log("The last value is:", last)
```

### More helpful Array methods

Mozilla documents everything you can do with JS lists, but here's a short list
of Array methods that I have found most useful.

- **[`shift`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array/shift)**:
  removes and returns the first item, shifting everything else down. The
  corollary to `pop`, but at the front of the list.
- **[`unshift`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array/unshift)**:
  adds one or more items to the front of a list. The corollary to `push`, but at
  the front of the list.
- **[`slice`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array/slice)**:
  returns a copy of a portion of a list, without modifying the original.
- **[`splice`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array/splice)**:
  inserts, removes, or replaces items in place at any index.
- **[`includes`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array/includes)**:
  returns `true`/`false` for whether a value is in the list.
- **[`indexOf`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array/indexOf)**:
  returns the index of the first matching value, or `-1` if not found.
- **[`find`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array/find)**:
  returns the first item matching a callback condition (like `filter`, but stops
  at the first match).
- **[`some`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array/some)**:
  returns `true` if at least one item satisfies a callback condition.
- **[`every`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array/every)**:
  returns `true` if all items satisfy a callback condition.
- **[`join`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array/join)**:
  combines all items into a single string, with a separator you choose (e.g.
  `", "`).

### Use arrays to store items to draw

If we have only a few things to draw, we can get by with writing `thingA`,
`thingB`, but this only works up to some limit before it becomes hard to manage.
If you have an arbitrary number of things, or just too many to deal with, lists
are the right tool to work with them.

```p5exercise autorun size="medium"
// Keep a list of recent mouse positions, and draw one circle per position.
// Newer positions get bigger circles, so the trail looks like it's fading
// out as it gets older.
let trail = []

// millis() counts up in milliseconds since the sketch started. Remember
// the last time we captured a point so we can tell how much time has
// passed since then.
let lastCaptureTime = 0

function setup() {
  createCanvas(400, 300)
}

function draw() {
  background("black")

  // Only grab a new point every 100ms, not every frame - otherwise the
  // trail would fill up almost instantly.
  if (millis() - lastCaptureTime > 100) {
    trail.push({ x: mouseX, y: mouseY })
    lastCaptureTime = millis()

    // Once we have more than 20 points, remove the oldest one (the one
    // at the front of the list) so the trail doesn't grow forever.
    if (trail.length > 20) {
      trail.shift()
    }
  }

  noFill()
  stroke("white")
  for (let i = 0; i < trail.length; i++) {
    // trail[0] is the oldest point, trail[trail.length - 1] is the
    // newest. map() turns that index into a diameter: 1px for the
    // oldest point, 20px for the newest, evenly spaced in between.
    const diameter = map(i, 0, trail.length - 1, 1, 20)
    circle(trail[i].x, trail[i].y, diameter)
  }
}
```

Some points I want to draw out from the solution code:

- The mouse position history is stored in a `trail` list. Did you see what
  _shape_ the items of that list had? They were objects that represent points,
  and had the shape `{x, y}`.
- To add to the end of the list, we used `trail.push(pt)`
- To remove from the beginning of the list (oldest items) we used
  `trail.shift()`
- Each trail bubble seems to get smaller over time, but this effect is done by
  looking at the bubble's position in the list. So we use an old-school for-loop
  so we can check its index. The resulting circle's diameter is dependent on the
  index value, which is an apt proxy for age since each point is sampled on a
  regular basis.

### Planets again, this time with lists

In the animation section we first saw a little solar system animation, but it
was implemented using a bunch of loose variables that were only related by a
"clever" naming convention. Then in the objects section, we cleaned that up so
the planets were all modeled with objects - but we still had to keep track of
each planet individually.

This is a great place to use lists. By placing planets in a list, we can
add/remove them, and have an arbitrary number of planets flying around a sun.

<Solution id="planets-with-lists">

```p5exercise autorun size="medium"
let planets = []

function setup() {
  createCanvas(300, 300)
  for (let i = 0; i < 6; i++) {
    planets.push(newPlanet())
  }
}

// picks reasonable-looking random values for one new planet
function newPlanet() {
  const rx = random(30, 140)
  return {
    rx: rx,
    ry: random(0.3, 1) * rx, // keep ry <= rx, so eccentricity stays sane
    speed: random(0.2, 1.2),
    diameter: random(10, 30),
    color: color(random(80, 255), random(80, 255), random(80, 255)),
  }
}

function draw() {
  background("black")

  const cx = width / 2
  const cy = height / 2

  // star: fixed at the center
  fill("#ffd51a")
  circle(cx, cy, 50)

  const t = millis() / 1000

  for (const planet of planets) {
    drawPlanet(planet, cx, cy, t)
  }
}

function drawPlanet(planet, cx, cy, t) {
  const angle = t * planet.speed
  const x = cx + planet.rx * cos(angle)
  const y = cy + planet.ry * sin(angle)
  fill(planet.color)
  circle(x, y, planet.diameter)
}

function keyPressed() {
  // UP_ARROW/DOWN_ARROW are strings in p5 v2 ("ArrowUp"/"ArrowDown"), so
  // compare against `code`, not the numeric `keyCode`.
  if (code === UP_ARROW) {
    addPlanet()
    return false // stop the arrow key from also scrolling the page
  } else if (code === DOWN_ARROW) {
    removePlanet()
    return false
  }
}

function addPlanet() {
  if (planets.length < 40) {
    planets.push(newPlanet())
  }
}

function removePlanet() {
  if (planets.length > 0) {
    planets.pop()
  }
}
```

A few things worth noticing in the solution:

- All dots live in one `planets` array instead of separate
  `planet1, planet2, planet3` variables. Drawing them takes a single `for..of`
  loop no matter how many there are - that's the "shorter code, more going on"
  payoff I promised.
- `newPlanet()` no longer takes arguments. It calls `random()` itself to pick
  the new planet's configuration, so every added planet still looks reasonable
  but different from the others.
- `keyPressed()` only pushes/pops the `planets` array - it doesn't draw anything
  itself. That follows the rule from the interactivity section: callbacks update
  state, and `draw()` does the rendering.
- `addPlanet`/`removePlanet` are small helpers that enforce the 0-40 bounds, so
  `keyPressed()` doesn't need to repeat that logic for both arrow keys.

let planets = []

function setup() {
  createCanvas(300, 300)
  for (let i = 0; i < 6; i++) {
    planets.push(newPlanet())
  }
}

function newPlanet() {
  const rx = random(30, 140)
  return {
    rx: rx,
    ry: random(0.3, 1) * rx,
    speed: random(0.2, 1.2),
    diameter: random(10, 30),
    color: color(random(80, 255), random(80, 255), random(80, 255)),
    trail: [],
    lastCaptureTime: 0,

function draw() {
  background("black")

  const cx = width / 2
  const cy = height / 2

  fill("#ffd51a")
  circle(cx, cy, 50)

  const t = millis() / 1000

  for (const planet of planets) {
    updateTrail(planet, t)
    drawTrail(planet, cx, cy)
    drawPlanet(planet, cx, cy, t)
  }
}

function updateTrail(planet, t) {
  if (millis() - planet.lastCaptureTime > 80) {
    planet.trail.push(t * planet.speed)
    planet.lastCaptureTime = millis()
    if (planet.trail.length > 15) {
      planet.trail.shift()
    }
  }
}

function drawTrail(planet, cx, cy) {
  noStroke()
  for (let i = 0; i < planet.trail.length; i++) {
    const angle = planet.trail[i]
    const x = cx + planet.rx * cos(angle)
    const y = cy + planet.ry * sin(angle)
    const diameter = map(i, 0, planet.trail.length - 1, 1, planet.diameter * 0.6)
    fill(planet.color)
    circle(x, y, diameter)
  }
}

function drawPlanet(planet, cx, cy, t) {
  const angle = t * planet.speed
  const x = cx + planet.rx * cos(angle)
  const y = cy + planet.ry * sin(angle)
  fill(planet.color)
  circle(x, y, planet.diameter)
}

function keyPressed() {
  if (code === UP_ARROW) {
    addPlanet()
    return false
  } else if (code === DOWN_ARROW) {
    removePlanet()
    return false
  }
}

    planets.push(newPlanet())
  }
}

function removePlanet() {

    planets.pop()

}

Modifying code to do "one more thing" is an important skill, whether you're
doing some exploratory art (like this), or you're doing serious business
engineering. In my experience, writing something new is rare, but incremental
work is common. So being able to start from some existing state and bending it
into some new shape is a good skill to develop.
