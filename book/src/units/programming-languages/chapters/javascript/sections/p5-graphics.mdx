# Shapes and Style

The p5.js framework we've used so far is just one of many, many ways to
conceptualize and program graphics. This can't be overstated: there is more to
graphics, and to programming generally, than p5.js. For many of you this is
where you're starting, but there is a whole world of alternatives out there.

That said, the p5 graphics system is similar in spirit to most other libraries
you'll find. So learning about graphics via p5 will give you portable intuition
to anything else you might use in the future.

The previous few chapters used a few p5.js graphics calls but I never really
explained what's going on. In this chapter, I'll correct that. My goal with this
chapter is to give a basis for how graphics work in p5 so you can get good
results. Unless you only aspire to change the background color. But if you want
more, read on!

The [p5.js reference documentation](https://p5js.org/reference/) is helpful, and
more complete than this discussion here, but it is an encyclopedia format, which
might not be great for people new to this.

## The Canvas is a Grid of Pixels

When you write `createCanvas(300, 150)` in a p5 program, this function creates a
graphics buffer that is 300 pixels wide and 150 pixels tall. By default, this
buffer has nothing in it - it isn't black or white (that would be _something_).
The buffer starts out as a grid of transparent pixels, yearning for you to paint
them.

This grid has a coordinate system where the origin, (0, 0) is at the _top left_
corner. The _x_ dimension grows as you move left. The _y_ dimension grows as you
move _down_. Does that feel weird to you? The coordinate system we're used to in
math class has _y_ growing upwards. But here, _y_ gets bigger as you go down.

This sketch illustrates the coordinate system on a 300 wide by 150 tall graphics
buffer. We've got three dots - green is at `(0, 0)` (top left), blue is at
`(300, 150)` (bottom right), and the red one is right in the middle at
`(150, 75)`. In the code, that last parameter `50` specifies the circle radius.

<Ask id="graphics-coords" mode="interacted" title="Coordinate system">

```p5exercise autorun size="medium"
function setup() {
  createCanvas(300, 150)
}

function draw() {
  background("white")
  fill("green")
  circle(0, 0, 50) // top-left
  fill("blue")
  circle(300, 150, 50) // bottom-right
  fill("red")
  circle(150, 75, 50) // middle
}
```

### Into the `Z` dimension

Did you check in on what happens when two shapes try to occupy the same space?
If you draw shape A, and then in a following step you draw shape B that overlaps
the first, the pixels for shape B will be drawn right on top of shape A. This
means that the order that you draw your shapes matter: draw your shapes from
back to front.

The _X_ dimension is left and right, and the _Y_ dimension is up and down. Given
a flat screen, what else is there? Some shapes are 'closer', and some are
'farther'. You can think of this as stacking, or layering, or Z-ordering. A 2D
buffer doesn't actually have a concept of the Z dimension, but it will
implicitly show you which objects were drawn more recently than others, because
their pixels will "win" over other shapes that are behind them.

If you didn't try it yet, go ahead and try making some circles that overlap
existing shapes. Then change the order that you draw them in the code, and
notice what graphic effects that gives.

## Shape Functions

In p5 and all other graphics libraries that I can think of, drawing a shape is
really about figuring how to relate numbers to the effect that you intend. A
circle has a location - X and Y coordinates - and a radius. At your discretion
(and we'll discuss this more farther down the page) the X and Y coordinate could
refer to one 'corner' of the shape. Or, instead of specifying a radius, you
could specify a diameter. These are all just different ways of describing the
geometry of a shape.

In p5, you draw a shape using a function call such as `circle(125, 50, 25)`.
These numbers are given in an order that implicitly makes sense to the `circle`
function... but might not make sense to you the programmer. There are other ways
to write functions to arguably be more intuitive. But p5 uses this approach, and
it is common.

The `circle `function takes `125`, then `50`, then `25`, but what do they mean?
Whoever made this function decided that the first number means the X coordinate,
followed by the Y coordinate, followed by the radius. They could have chosen to
put the radius first, or switched the X and Y coordinates.

The library designers chose that order they thought it would make sense to you.
But even experienced programmers forget the order of arguments, which is why
documentation and editor hints are so nice to have. But usually a library is
consistent about argument ordering so once you learn their conventions, it is
easier to remember and apply.

### Have some style

We'll see many different kinds of shape drawing functions in use below. When you
use any drawing function, they will be drawn using a current _style_. This
refers to what graphic attributes are used: the color and thickness of lines,
the color of the background, among others.

Here is list of frequently used graphic styles. Where I write it like
`something(..)` with the dots, that means there are different variations that
take different arguments.

- `fill(..)` - sets the fill color for shapes and text, e.g. `fill("blue")`
- `noFill()` - disables any existing fill value
- `stroke(..)` - sets the stroke color for shapes and text, e.g. `stroke("red")`
- `noStroke()` - disables any existing stroke value
- `strokeWeight(n)` - sets the stroke thickness to `n` pixels wide, e.g.
  `strokeWeight(3)`

Study this sketch:

### `line`

A line in a graphics library generally means a line _segment_ - you tell it
which two points to begin and end at, and it will connect them in whatever style
you've established.

The syntax is like this:

```js
line(x1, y1, x2, y2)
```

The `x1` and `y1` are the two components of the first point, `x2` and `y2` are
for the second. This is a convention you'll see in other calls - lists of points
alternate x and y, and one point follows the other.

<Ask id="graphics-line" mode="untracked" title="line">

```p5exercise autorun size="small"
function setup() {
  createCanvas(150, 150)
}

function draw() {
  background("black")

  strokeWeight(10)
  stroke("yellow")
  line(10, 50, 140, 50)

  strokeWeight(5)
  stroke("lightBlue")
  line(100, 10, 100, 140)

  strokeWeight(8)
  stroke("red")
  line(10, 100, 140, 100)

  strokeWeight(5)
  stroke("lightGreen")
  line(50, 10, 50, 140)
}
```

</Ask>

### `rect` and `square`

Rectangles and squares are straightforward as well. You technically don't need
the `square` function since that's just a particular kind of rectangle, but it
is convenient.

```js
rect(x, y, width, height, [corner radius])
square(x, y, size, [corner radius])
```

With `rect`, you indicate `x` and `y` for the _top left corner_, and the `width`
and `height` do the obvious thing. Personally I never remember that it is
spelled `rect` and not `rectangle`. Maybe you have better luck.

With `square`, instead of unique width and height you give the `size`, which is
applied to both dimensions.

In both cases, you can optionally give a radius to make the corners a bit
rounded.

<Ask id="graphics-rect-square" mode="untracked" title="rect and square">

```p5exercise autorun size="small"
function setup() {
  createCanvas(150, 150)
}

function draw() {
  background("black")

  fill("green")
  rect(20, 60, 110, 70, 6)

  fill("white")
  square(20, 20, 30)
  square(60, 20, 30, 8)
  square(100, 20, 30, 15)
}
```

</Ask>

You probably noticed that one of those squares looks suspiciously like a
circle... even though we used the `square` function. Bonkers! This is because
the radius is big enough that the corners are so rounded that it visually
becomes a circle.

### `ellipse` and `circle`

There's a better way to make a circle, and we've seen it many times before. But
for posterity, here is `circle` and its good friend, `ellipse`:

```js
ellipse(x, y, width, height)
circle(x, y, diameter)
```

Importantly, the `x` and `y` values here by default refer to the _center_ of the
shape. This is different from `rect` and `square`. You have my permission to
find this confusing! But maybe this does make sense, since we often think of
circles as where they're centered.

For an ellipse, we provide the width and height. For a circle, we give the
diameter.

This canvas below is 150x150, so we can put an ellipse and circle centered at
(75, 75) to make an eye, staring straight into your very being:

<Ask id="graphics-ellipse-circle" mode="untracked" title="ellipse and circle">

```p5exercise autorun size="small"
function setup() {
  createCanvas(150, 150)
}

function draw() {
  background("black")
  fill("white")
  ellipse(75, 75, 150, 55) // canvas center
  fill("green")
  circle(75, 75, 50) // also canvas center
}
```

</Ask>

### Stateful modes for drawing rectangles and ellipses

In the last two sections I mumbled vaguely about how rectangles/squares are
defined by the _top left corner_, while circles/ellipses are defined by their
_center_. You can change this behavior so the numbers are interpreted
differently.

For rectangles and squares, use `rectMode`, with an argument:

```js
// determine how to interpret the rect/square coordinate
rectMode(CENTER) // use the center of the rect/square
rectMode(CORNER) // use the top left corner of the rect/square
rectMode(CORNERS) // top left and bottom right - only for rectangles
rectMode(RADIUS) // center followed by half the width and height
```

There's a similar setup function for circles and ellipses called `ellipseMode`:

```js
ellipseMode(CENTER) // use the center of the circle/ellipse
ellipseMode(CORNER) // use the top left corner of the circle/ellipse
ellipseMode(CORNERS) // top left and bottom right - only for ellipses
ellipseMode(RADIUS) // center followed by horizontal and vertical radii
```

Importantly, once you've set a `rectMode` or `ellipseMode`, that state will
remain until you change it. The change is _global_, meaning that if you're in a
function that sets the mode, anything that runs later will be in that mode until
you change it. (See the section on `push` and `pop` for a way to manage this
easily.)

Here is the same rectangle call used several times with the different drawing
modes. I only change the color so you can tell them apart more easily.

<Ask id="rect-mode" mode="interacted" title="rectMode">

```p5exercise autorun size="medium"
function setup() {
  createCanvas(150, 150)
}

function draw() {
  background("black")
  noFill()
  strokeWeight(3)

  rectMode(CENTER)
  stroke("green")
  rect(50, 50, 30, 80)

  rectMode(CORNER)
  stroke("red")
  rect(50, 50, 30, 80)

  rectMode(CORNERS)
  stroke("white")
  rect(50, 50, 30, 80)

  rectMode(RADIUS)
  stroke("blue")
  rect(50, 50, 30, 80)
}
```

</Ask>

### Polygons with `beginShape` / `vertex` / `endShape`

We can draw shapes with arbitrary polygon geometry using `beginShape`, followed
by whatever geometry building you need, and finishing with `endShape`. To keep
things simple for now, I'll build geometry using the `vertex` function. But be
aware that there are other ways to define polygons.

Here's that process:

```js
beginShape()
vertex(x1, y1)
vertex(x2, y2)
vertex(x3, y3)
// ...as many vertices as you like
endShape(CLOSE)
```

<Ask id="graphics-polygon" mode="interacted" title="Polygons">

```p5exercise autorun size="medium"
function setup() {
  createCanvas(150, 150)
}

function draw() {
  background("black")
  stroke("lightGreen")
  strokeWeight(5)

  noFill()
  beginShape()
  vertex(75, 10)
  vertex(140, 130)
  vertex(90, 95)
  vertex(10, 130)
  endShape(CLOSE)
}
```

</Ask>

You can call `beginShape` with a few different arguments that will tell p5 how
to interpret the geometry that you place between that and the `endShape` call.
The two you _might_ want any time soon are `POINTS` and `LINES`. There are
others but they're advanced.

As you can see, `endShape` takes an optional argument: `CLOSE` will connect the
last point you specified with the first one. Without this argument, it doesn't
connect them (though it behaves funny for filled shapes).

Play with the code above by changing the arguments to `beginShape` and
`endShape`, and moving the points around.

Important safety tip! If you `beginShape`, you really better `endShape`! This is
because the graphics library goes into a special state where it is looking for
certain things - `vertex` calls among others that I'm coyly not mentioning
(yet). Also, don't use normal geometric calls like `circle` while you're
defining a shape, because they won't work.

## Style is State

Throughout this chapter I've also referred to the graphics library as
remembering things, like what the fill color is, or if we're defining a shape.
This memory is called _state_. Something that is stateful will 'stick' until it
is changed. This is helpful in that you don't need to repeat yourself all the
time. And since this state is held for the entire program, it is called _global
state_.

Global state can cause trouble because you might not remember or even be aware
that some state (like the stroke weight) has a value that isn't right for your
use case, and then you'll be like _"whyyyyyyyy does it look like this?"_ It will
happen, you will shake your firsts in anger, and then you will have a reason to
pay more attention to global state. The section on `push` and `pop` below
addresses this

There are lots of different kinds of state. Style is one of them: colors for
stroke and fill, line weights, booleans that determine if shapes or text are
stroked or filled. Think of this like when you're drawing - you're hold a red
marker, and whatever you draw will be red; to change to blue you give up the red
and pick up the blue, now whatever you draw is blue. The pen in your hand is the
graphic state.

### `push` and `pop`

Beyond the graphics state already mentioned like colors and stroke properties,
there are many other kinds of state that the graphics library understands. We'll
talk about many of these things later on.

There is a deceptively powerful way of managing this global state using the
`push` and `pop` functions. Imagine that you can bundle all the state values and
put them on a sheet of paper - background color is blue, stroke color is white,
and fifteen other things. When you want to record the overall graphical state at
this moment, you call `push()`, which 'pushes' the sheet of paper onto a stack
of similar sheets. You can do this over and over - growing your stack of state
pages each time. Then, when you want to back out, you `pop()` from this stack,
and this resets the graphic state to whatever was on the topmost sheet.

This is actually foreshadowing a _data structure_ that you might learn about in
the back half of this book. A _Stack_ data structure works like I just
described: you push data onto it, then pop data off the top. This means that the
data that was added most recently is the first in line to get popped off.

This is a perfect use case for storing and restoring graphic state.

<Ask id="graphic-stack-push-pop" mode="untracked" title="push and pop">

```p5exercise autorun size="small"
function setup() {
  createCanvas(150, 150)
}

function draw() {
  background("black")
  fill("blue")
  stroke("white")
  strokeWeight(10)
  circle(50, 75, 30)
  push() // save blue fill, white stroke 10px thick
  fill("red")
  stroke("green")
  strokeWeight(2)
  circle(75, 75, 30)
  pop() // restore previously pushed state
  circle(100, 75, 30)
}
```

</Ask>

Another way to think of this like an app that supports undo. As you work, you're
pushing edits onto a stack. When you want to back out one step, you hit undo,
which pops the most recent edit from a stack. You can push as much as you like,
and you can pop so long as there's something on the stack to remove.

In the example above, it only has one `push`/`pop` pair. But you can nest them
as shown below:

<Ask id="graphics-stack-push-pop-nested" mode="untracked" title="Nested push and pop">

```p5exercise autorun size="small"
function setup() {
  createCanvas(150, 150)
}

function draw() {
  background("black")
  fill("blue")
  stroke("white")
  strokeWeight(10)
  circle(50, 75, 30)
  push() // save blue fill, white stroke 10px thick
  fill("red")
  stroke("green")
  strokeWeight(2)
  circle(75, 75, 30)
  pop() // restore previously pushed state
  circle(100, 75, 30)
}
```

</Ask>

Something that is critically important: you'll need to balance your `push` and
`pop` statements. I'll promote a healthy habit of writing drawing functions with
push and pop at the beginning and end:

```js
function drawSomething() {
  push()
  // whatever state changes I make here will be popped
  // before returning - this is a safe way to roll.
  pop()
}
```

If you're reading this chapter in sequence, this might look new to you because
we haven't really discussed functions yet. Suffice it to say that `push` and
`pop` are extremely useful, and when you do start writing your own drawing
routines, this is a good pattern to use.
