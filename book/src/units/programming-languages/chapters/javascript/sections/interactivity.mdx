# Interactivity

So far we've written p5.js sketches that create _static_ images. This means they
don't change over time, or in response to what the user does. We're going to
learn about _interactivity_.

p5.js can handle almost any input that your browser knows about. For starters,
you get support for mouse and keyboard right out of the box.

## Lifecycle functions `setup` and `draw`

A p5 sketch that doesn't react to the environment or the user is considered
static - it won't need to change after it has rendered once. But a program that
responds to interactivity has to be prepared to re-render on a moment's notice.

p5 has lifecycle functions for covering this. The `setup` function is called
_one time_ at the beginning of the sketch's life. This is the appropriate place
to configure the canvas, load resources, and whatever other one-time operations
you might need to take care of so that they're ready for the future. And if your
sketch is static, you can even draw graphics in the `setup` function.

The other main lifecycle function is called `draw`, and we've seen it many times
already but haven't really described it. The `draw` function is invoked over and
over by p5 - you don't call it yourself. If your sketch is static, you can omit
this function entirely.

Each call to `draw` starts and finishes — and in the gap before the next one, p5
is still running, capturing input and getting ready for the next cycle. _That's
what allows the program to be interactive in the first place_.

{/* prettier-ignore-start */}

The timing that p5 uses to repeatedly invoke the `draw` function is called the
<Term>frame rate</Term>, and you can change it by calling `frameRate(n)`, where
`n` is the number of times per second it should be called.

{/* prettier-ignore-end */}

By default the frame rate is 60, which means it will draw to the screen at 60
Hertz. This works out to about every 16 milliseconds - fast enough that it is
difficult for us humans to discern one frame from the next. A fast frame rate
gives the appearance of nice fluid motion.

What this means for you the programmer is that whatever you do during a `draw`
call, it must complete quickly, otherwise you'll get choppy graphics behavior
called "jank" - dropped frames because the computer is doing too much. Avoid
jank.

## Variables, Callbacks, and Utility Functions

There are three main ways for you to work with interactivity: through variables,
event callbacks, and utility functions.

### Interactivity Variables

p5.js has special variables with information about mouse and keyboard state.

| Variable         | Description                                                               |
| ---------------- | ------------------------------------------------------------------------- |
| `mouseX`         | Horizontal position of the mouse, in pixels                               |
| `mouseY`         | Vertical position of the mouse, in pixels                                 |
| `movedX`         | How far the mouse moved horizontally since the last frame                 |
| `movedY`         | How far the mouse moved vertically since the last frame                   |
| `mouseButton`    | Object with `left`, `right`, `center` booleans for which buttons are down |
| `mouseIsPressed` | Whether any mouse button is currently being held down                     |
| `key`            | The most recently pressed key, as a string                                |
| `keyCode`        | The numeric code of the most recently pressed key                         |
| `keyIsPressed`   | Whether any key is currently being held down                              |

You can _read_ these variables at any time, including in the `draw` function.
p5.js keeps them up to date as the user moves the mouse or types, so whatever
`draw` reads is the latest value — and by default `draw` runs 60 times per
second.

### Interactivity Callbacks

Another primary way to get interactivity information is to define an event
callback function:

| Callback          | Description                                                |
| ----------------- | ---------------------------------------------------------- |
| `mouseMoved()`    | Called when the mouse moves, with no button pressed        |
| `mouseDragged()`  | Called when the mouse moves while a button is pressed      |
| `mousePressed()`  | Called once when a mouse button is pressed                 |
| `mouseReleased()` | Called once when a mouse button is released                |
| `mouseClicked()`  | Called after a mouse button is pressed and released        |
| `doubleClicked()` | Called when the mouse is clicked twice in quick succession |
| `keyTyped()`      | Called when a key that produces a character is pressed     |
| `keyReleased()`   | Called once when a key is released                         |
| `keyPressed()`    | Called once when a key is pressed                          |

This means that you define any of these functions, and p5 will call your version
of that function as appropriate. It does this between `draw` calls. This means
you can get the event, write some state, and then use that state during the next
`draw` call.

{/* prettier-ignore-start */}

For example, say you have a sketch that shows a lightbulb. When the user presses
the <Kbd>[</Kbd> key, we want to turn the light on, and <Kbd>]</Kbd> turns it 
off. Your callback could look like this:

{/* prettier-ignore-end */}

```js
function keyTyped() {
  if (key === "[") {
    lightbulbOn = true
  }
  if (key === "]") {
    lightbulbOn = false
  }
}
```

Importantly, you should notice that we're not actually drawing anything here!
We're only recording the state we need (`lightbulbOn` is either `true` or
`false`). Then the next time our `draw` function is run, we can use that to
render the lightbulb as expected.

As a rule of thumb, callback functions should only set state, not draw. (You
technically _can_ draw from inside one, but it'll just get erased on the next
`draw()` call unless you also call `noLoop()`.)

### Utility Functions

There are a few utility functions that you can call at any time to get
information. These are convenience functions to help save some typing. You can
use these in the `draw` function. The one that you're likely to want right away
is `keyIsDown(k)`.

Use utility functions whenever you want - under the hood they use values that
essentially mirror the provided variables like `key` and `keyCode`.

### When and how to use interaction variables and callbacks

So to summarize:

1. **Declare and initialize** variables at the top, using _let_ so they can be
   changed to store whatever you're tracking.
2. **Read** variables during the `draw` function.
3. **Write** variables during the callback functions.

```p5sketch autoplay width=150 height=150
// Interactive Face
//
// Sketch is for 2nd week students, so limited syntactic range.

// constants for special locations
// canvas
const w = 150;
const xMid = w / 2;
const h = w;
const yMid = h / 2;

// eyes
const eyeRadius = 10;
const eyeY = yMid - 30;
const eyeSpreadX = 20;
const eyeLeftX = xMid - eyeSpreadX;
const eyeRightX = xMid + eyeSpreadX;

// pupils
let pupilRadius = 5;
let pupilLeftX = eyeLeftX + 2;
let pupilLeftY = eyeY + eyeRadius / 8;
let pupilRightX = eyeRightX - 2;
let pupilRightY = eyeY + eyeRadius / 8;
const pupilColorCount = 4;

// four possible pupilColors
const pupilColor0 = "#000";
const pupilColor1 = "#243ba3";
const pupilColor2 = "#47350f";
const pupilColor3 = "#118246";
let pupilIndex = 0;
let pupilColor = pupilColor0;

// nose
const noseX = xMid;
const noseY = yMid;
const noseW = 20;
const noseH = 10;

// mouth - a circle arc, so define the circle and angles
const mouthCX = xMid;
const mouthCY = yMid - 20;
const mouthRad = 100;
const mouthStartAngle = (1 / 4) * Math.PI;
const mouthEndAngle = (3 / 4) * Math.PI;
const mouthFlatY = yMid + 30;
const mouthFlatW = 70;
let mouthIsSmiling = true;

function setup() {
  createCanvas(w, h);
}

function draw() {
  background("#ddd");

  // --------------------------- eyes
  strokeWeight(1);
  fill("#fff");
  // left
  circle(eyeLeftX, eyeY, eyeRadius * 2);
  // right
  circle(eyeRightX, eyeY, eyeRadius * 2);

  // --------------------------- pupils
  fill(pupilColor);
  if (keyIsDown(LEFT_ARROW)) {
    pupilRadius = Math.max(1, pupilRadius - 0.1);
  }
  if (keyIsDown(RIGHT_ARROW)) {
    pupilRadius = Math.min(eyeRadius - 2, pupilRadius + 0.1);
  }
  circle(pupilLeftX, pupilLeftY, pupilRadius * 2);
  circle(pupilRightX, pupilLeftY, pupilRadius * 2);

  // --------------------------- nose
  // two lines
  const nX1 = noseX;
  const nY1 = noseY - noseH / 2;
  const nX2 = noseX - noseW / 2;
  const nY2 = noseY + noseH / 2;
  const nX3 = noseX + noseW / 2;
  const nY3 = nY2;
  line(nX1, nY1, nX2, nY2);
  line(nX2, nY2, nX3, nY3);

  // --------------------------- mouth
  noFill();
  // two mouth styles - smile and flat
  if (mouthIsSmiling) {
    arc(mouthCX, mouthCY, mouthRad, mouthRad, mouthStartAngle, mouthEndAngle);
  } else {
    line(xMid - mouthFlatW / 2, mouthFlatY, xMid + mouthFlatW / 2, mouthFlatY);
  }
}

// make pupils follow the mouse
function mouseMoved() {
  // update pupil positions based on mouse position, each eye center,
  // while preventing pupils from being positioned outside of the eye
  const maxOffset = eyeRadius - pupilRadius;

  const mouse = createVector(mouseX, mouseY);

  const eyeLeft = createVector(eyeLeftX, eyeY);
  const deltaLeft = p5.Vector.sub(mouse, eyeLeft);
  deltaLeft.limit(maxOffset);
  pupilLeftX = eyeLeft.x + deltaLeft.x;
  pupilLeftY = eyeLeft.y + deltaLeft.y;

  const eyeRight = createVector(eyeRightX, eyeY);
  const deltaRight = p5.Vector.sub(mouse, eyeRight);
  deltaRight.limit(maxOffset);
  pupilRightX = eyeRight.x + deltaRight.x;
  pupilRightY = eyeRight.y + deltaRight.y;
}

// up/down keys control the mouth shape
function keyPressed() {
  if (key === " ") {
    mouthIsSmiling = !mouthIsSmiling;
  }
  if (key === "ArrowUp") {
    // this approach is not recommended - when we learn
    // about lists you'll have a much better way
    pupilIndex = (pupilIndex + 1) % pupilColorCount;
    if (pupilIndex === 0) {
      pupilColor = pupilColor0;
    } else if (pupilIndex === 1) {
      pupilColor = pupilColor1;
    } else if (pupilIndex === 2) {
      pupilColor = pupilColor2;
    } else if (pupilIndex === 3) {
      pupilColor = pupilColor3;
    }
    return false; // prevents page from receiving this & scrolling
  }
}
```

</Ask>

### Pupils following mouse

The trickiest part in this interactive sketch is how the pupils creepily follow
the mouse position. There are many ways to do this, but my solution involves
using vectors (see the arithmetic section).

If you've never used vectors before, don't despair if the solution is baffling
when you first see it. This is the kind of thing that you really only start to
understand by building with it.

Note that each eye is independent of the other. You might want to have one pupil
follow the mouse to start with, for comedic relief.

```p5exercise autorun size="medium"
function mouseMoved() {
```

```p5exercise autorun size="small"
  // while preventing pupils from being positioned outside of the eye
  const maxOffset = eyeRadius - pupilRadius;
```
