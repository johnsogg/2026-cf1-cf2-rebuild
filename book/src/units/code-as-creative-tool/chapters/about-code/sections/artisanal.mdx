# Artisanal Code in the Age of AI

I want to tell the tale of people writing code, and how AI has changed the game.

## _Dramatis personae_

**Humans.** Meat-based programmers powered by sandwiches. Motivations include:
building things that don't break, having and expressing ideas. Wants to have
pride in their work.

**Computers.** Silicon-based machines powered by electricity that execute
whatever instructions are given to them. They lack motivation, or awareness of
what they're doing.

**AI Coding Agents.** The newcomer: power-hungry algorithms performing
statistical inference. Has no sense of pride or shame, but simulates both pretty
well if asked.

## Until Recently

People who wrote computer code were responsible for everything: what the
software did, for whom, in what way. Humans had to program every beep, all the
graphics, every data fetch. Software could be complex, but it was written by
people who (collectively) understood all the details. Or most of them, at least.

Along the way we built tools to help manage all that detail-oriented work:
compilers, source control management, editors, package managers, debuggers and a
hundred other kinds of software gadgets. They all served to reduce the mental
burden on the programmer to let them think, design, and engineer more
effectively. And learning and using them are a big part of the developer's
trade.

Despite this wide array of fancy tools, the programmer remains responsible for
everything. The computer still simply executes what it is told to without
understanding why, because it possesses no ability to care. If the programmer
intends to do one thing but got the details wrong, the computer won't magically
fill in the gaps. The humans had to spot the error, learn, and fix it.

It is exactly this kind of puzzle solving activity that draws so many people to
software development. But AI is changing this in a dramatic way.

## Enter AI

Coding agents as we know them today (2026) do an amazing job of writing code.
They're confident in their methods and results, and lull you into believing that
their work is solid. Despite this confidence, the code they write is still
merely _plausible_. It is extremely easy for a developer to simply accept what
the AI has written as good enough - it seems to do the right thing in the right
way, and is clear enough for the next person (or chatbot) to maintain. But is
any of that _true_?

Sometimes. Coding agents are constantly getting better. Who knows what the
future holds? But for the foreseeable future, AI is only effective when operated
by somebody who understands the trade: how to code, how the tools work, and
(importantly) how to speak so the AI understands clearly and unambiguously what
is intended. The human's mental model informs the prompts and shapes what the AI
generates.

If you're just learning to code, you will be tempted to use AI to write for you.
And there is a lot to learn by studying AI-generated output, but only if you
have the skill to make sense of it. There's an obvious danger to letting it
_think_ and _understand_ for you as well. Learning is not a spectator sport. You
have to be actively involved and be prepared for struggle.

Since LLMs are so new, nobody really knows how they should fit in to an
educational setting. For your part as somebody learning this craft, my advice is
to pay attention to that struggle: if it seems too easy, you're probably cutting
corners.

## Code is a detail-oriented building medium

Just as you can build with wood, wires, or words, you can build with code.

Writing code is a detail-oriented art. If you don't get the details right, your
outcome will generally not be what you're after. This can be very frustrating.
And many people will hit that frustration, and wrongly concludes that code just
isn't something they can do.

If this sounds like you, I want you to know that you're not alone. I've worked
with hundreds of computer science and design students, and have seen many people
flip their perspective, and I am certain you can too.

Obviously, writing code is not the only activity that requires attention to
detail. You would not want your brain surgeon to get it _pretty close_ - you
want them to be _exact_!

And of course, we can measure what 'exact' means by way of tolerances, in brain
surgery or elsewhere. It is a fluid concept that depends on what you're doing.

Some details just don't matter, but knowing which ones matter, to whom, and
when, can make the difference between success, failure, and points between. This
is a skill learned by experience, and the only way I know of to become an
experienced programmer is to write a lot of code.

## To Whom It May Concern: Human, AI, Computer

Newcomers to this art might rightly think: _Why should I learn the details if an
AI is going to take care of it for me?_ This is a good and rational question. It
is true that LLMs have changed the dynamic of how code gets written. However, a
coding agent is just operating on linguistic and statistical patterns, and what
makes sense to an experienced human practitioner will make sense to a robot (and
vice versa).

When we're discussing the topic of which details matter, and _to whom_, the
distinction between human and AI is often not very meaningful. For example,
consider the following:

```ts
favoriteColor = 1776
independenceYear = "Orange"
```

For an LLM or a human, this is obviously wrong. Based on the names,
`favoriteColor` should be _a color_; `independenceYear` must be a plausible
year. To do otherwise is just confusing. But we're assigning the year to a color
variable, and a color to the year variable. We know it is wrong because the
names and values don't make sense. Humans and LLMs can spot that easily.

At the same time, the above is _completely correct_ Javascript code, and your
computer will execute it without error. It might not _mean_ what you _want_ it
to mean, but a JavaScript interpreter is not capable of learning or caring what
your intentions are, or what the variable names mean. It simply executes the
code it is given.

In a sense, a programmer who writes code by hand has a lot in common with an AI
who works tirelessly: the hard part is understanding intentions, consequences,
purpose, and translating that into software.

But AI agents do not (yet) have a sense of shame preventing them from writing
awful code. Nor do they (yet) feel pride in having written clear, maintainable
code. And personal experience has taught me that AI can create a complete mess
of a codebase faster than any human.

## Why Learn Artisanal Coding?

This AI tangent gave a little context about what is going on in the software
industry, and acknowledged the prevalence of coding agents. Maybe you're looking
to the future and you think _AI will write all code, what is the purpose of
learning it?_

I have two responses to this. The first is practical and might change as AI gets
better. The second is intellectual, and will serve you well no matter what.

So, the practical: As mentioned above, current AI coding agents perform
statistical inference, so they are only capable of working within the patterns
contained in their training data and whatever is given to them at runtime. They
take shortcuts, write unmaintainable code, or confidently assert that it is
bug-free when that is far from the case. The more skilled and intuitive the
human programmer is, the better they can guide the agent to produce quality
code. And all that starts with learning the fundamentals of programming.

Next, the intellectual. If you lack the vocabulary or conceptual framework for
articulating what you want, the AI will certainly not be able to build it. And
if you want the result to be improved, maintained, made efficient for use at
scale, you have to plan for the future.
