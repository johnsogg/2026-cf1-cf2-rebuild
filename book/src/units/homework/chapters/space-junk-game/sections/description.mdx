# Space Junk Game

Unlike most of the previous homework assignments, this one has a definite
description of what I want you to do. The point is to build something to
somebody else's arguably bad specification, with a clear, testable rubric.

And, just so you know that I know, and now _we all know_: it is also quite
AI-friendly. The thing that makes this well-defined for a human programmer is
exactly the quality that makes it easy for an AI: unambiguous, clear English
language. I don't claim to have written the perfect specification; only that it
is good enough to one-shot a playable video game.

Of course, having an LLM do your thinking and learning for you is Bad(tm).

I've made this homework as something that you can step through and have some
productive struggle along the way. You should be able to do this the old
fashioned way (e.g. not using AI).

## Overview

This is a game where you control a little space ship (the "Magpie") charged with
the unenviable task of keeping space clean. This homework builds the first part
of it so it is recognizable as a game, but you won't be asked to write the
entire thing.

In the full form of this game, you pilot your ship to get near a piece of
floating space junk, capture it with an energy beam, and return it to a waiting
cargo ship (the "Mothership"). Once you've captured all the junk on the board,
Magpie rejoins the Mothership and they zip off to the next area with space junk.
You get points for collecting junk, with a bonus for doing it faster. You also
get points for completing levels. On some levels, there are hazards that will
cause the untimely end of the Magpie. Fortunately the Mothership keeps spares
around, so you have several ships to ruin.

In this homework, you'll write the code to render the game elements, fly the
Magpie, and catch junk with a tractor beam. Delivering junk to the Mothership,
the timer, the score, and the lives display come in the next homework. There is
also only one level to play, and no hazards to avoid.

Some other misc things I want to point out:

In the running sketches, you can always press <Kbd>~</Kbd> to turn on debug
mode. This is something the Space Junk project code does for you - there's
nothing magic about it, and I recommend you steal and re-purpose this idea for
your other work as well. This shows each object's position and velocity, plus

Many functions take a `delta` parameter. This means the number of milliseconds
since the last frame. We can pause the game, so when that happens the `delta`
gets capped at some number (50, I think). We're using p5's `deltaTime` as the
basis for this.

Values that record rate-of-change describe change per second. Velocity is
expressed as pixels per second, rotation as radians per second. So you can
convert those to -per-millisecond with the clever use of division:
`delta / 1000`.

The tunable values are written as `SCREAMING_CAPS` and are static constants
inside various classes, like `Game.JUNK_CATCH_TIME_MS` is a number you can mess
with to adjust gameplay.

## Phase 1: Draw the ships and the junk (3 points)

Your first mission is to turn those ugly rectangle wireframes into good looking
game elements. You're going to edit these static functions:

- `Magpie.drawMagpie`
- `Junk.drawJunk`
- `Mothership.drawMothership`

Each is drawn according to its own `(0, 0)` origin. So you don't have to know or
care what the rest of the game state looks like, and you don't even need to care
where your origin is on the screen. All you need to know is that when your
`drawThing` function runs, the graphics transforms are already set up, so you
just render your element as though it was the only thing in the universe,

Specific guidance on each of our game elements are as follows.

### Spec - Magpie

The Magpie is drawn as a rounded rectangle. It has a sharper rectangular piece
on the bottom, and a window on the right side.

- Remember to `push` right away, and `pop` as the last thing it does.
- Rotated by `rotation`. You'll likely want to do this first, inside `push/pop`.
- Dome: rounded rect, `Magpie.DOME_WIDTH` by `Magpie.DOME_HEIGHT`, centered on
  `(0, 0)`. Pick whatever corner radius floats your boat.
- Platform: plain or rounded rectangle, `Magpie.PLATFORM_WIDTH` by
  `Magpie.PLATFORM_HEIGHT`, centered on the dome's bottom edge. It's a little
  wider than the dome.
- Window: small rect, `Magpie.WINDOW_WIDTH` × `Magpie.WINDOW_HEIGHT`, inside the
  dome against its right edge, just above center
- Ignore the `beam` parameter for now (that's for Phase 3)

### Spec - Mothership

The Mothership is rendered as a longer rectangular ship with rounded corners.
(Being a cargo ship, they don't spend the extra cash on aesthetics.) It has a
row of circular porthole-style windows going down the center.

- `push/pop` as first and last things, followed by `rotate`.
- Body: rounded rect, `Mothership.WIDTH` × `Mothership.HEIGHT`, corner radius
  `Mothership.CORNER_RADIUS`, centered on (0, 0)
- Portholes: `Mothership.NUM_PORTHOLES` circles, `Mothership.PORTHOLE_DIAMETER`
  across, evenly spaced along the middle. Hint: use a loop and place circles
  along a line.

### Spec - Space Junk

Space junk is rendered as simple circles. Colliding with junk is harmless, as
both the Mothership and Magpie have special shielding that makes the junk pass
straight through them, somehow. In the future, there is magic!

- Follow above advice about `push/pop` but don't need to worry about `rotate`
  because it is a circle.
- Filled circle, `Junk.DIAMETER` across, centered on (0, 0)

## Phase 2: Fly the Magpie (3 points)

OK, so now we're going to move on. Pun intended!

Use the WASD keys to pilot the Magpie around. There is no atmosphere, so...
objects at motion stay at motion.

You'll edit these functions:

- `Physics.move`
- `Physics.rotate`
- `Physics.thrust`
- `Inputs.handleKeyDown`

One neat thing about this is that once you implement a function like
`Physics.move`, everything that uses it will also start moving. (Remember,
laziness is a virtue!)

The `move` function already has some code to keep your object on screen. You'll
want to edit the part above that. The mission is to use `delta` and the velocity
(`this.dx`, `this.dy`) to compute the object's new world location (`this.x`,
`this.y`). My solution was three lines of code.

`rotate` is similar in spirit, and even shorter: one line of code could do it.

The <Kbd>w</Kbd> and <Kbd>s</Kbd> keys control forward and reverse thrust.
Calculating thrust is a little less straightforward. You'll need to calculate
the thrust per _second_, but you're given a `delta` that is in milliseconds.

Your ship has a rotation. So we need to be smart about calculating the new
velocity based on the previous velocity, the object's rotation, and the thrust
amount per second.

Translate the following math into code, and you're good to go:

$$
\begin{aligned}
\text{amt} &= \text{accel} \cdot \frac{\text{delta}}{1000} \\
dx_{\text{next}} &= dx + \text{amt} \cdot \sin\theta \\
dy_{\text{next}} &= dy - \text{amt} \cdot \cos\theta
\end{aligned}
$$

The reason $x$ is associated with $\sin$ and $y$ with negative $\cos$ is because
'up' is in the negative $y$ direction.

### Controls

Edit `input.js` `handleKeyDown` to support the following. As an example:

```js
if (keyIsDown("w")) {
  this.magpie.physics.thrust(Inputs.THRUST, delta)
}
```

Your movement controls will update the Magpie's `physics` object, and the space
key updates its beam state (you can hold off on that until the next phase).

- <Kbd>w</Kbd>: thrust forward, at `Inputs.THRUST`
- <Kbd>s</Kbd>: reverse thrust, at `Inputs.REVERSE_THRUST` (weaker)
- <Kbd>a</Kbd>: rotate counter-clockwise, at `Inputs.TURN_RATE`
- <Kbd>d</Kbd>: rotate clockwise, at `Inputs.TURN_RATE`
- Hold keys down: check them every frame with `keyIsDown()`, not with
  `keyPressed()`

### Spec

- `move`: position changes by velocity x elapsed time. Velocity is pixels per
  second; `delta` is milliseconds.
- `rotate`: rotation changes by rate x elapsed time. Positive is clockwise
  (because positive y points down).
- `thrust`: velocity changes in the direction the ship faces. Rotation 0 faces
  up, so forward is `(sin(rotation), -cos(rotation))`.

### Done when

- Junk and the Mothership drift slowly
- The Magpie turns both ways, thrusts forward and back, and keeps drifting when
  you let go
- Every rate is multiplied by elapsed time (`delta / 1000`), not applied once
  per frame (e.g. `frameCount` shouldn't be involved)

## Phase 3: Tractor beam (3 points)

In this phase, we'll add support for the tractor beam so we can catch junk.
Delivering it to the Mothership comes in the next homework.

First, add support for holding the <Kbd>Space</Kbd> (Space) key. While that key
is held down, show the tractor beam. When the player releases <Kbd>Space</Kbd>,
the beam stops. When there is junk positioned in the beam for more than some
threshold of time, it is "caught".

For this phase, you'll implement these:

- `Magpie.drawMagpie` (the beam part)
- `Magpie.enableBeam`
- `Inputs.handleKeyDown` (the <Kbd>Space</Kbd> part)
- `Game.resolveBeam`

You're given the function `Magpie.beamContains(point)` that tells you if a point
(the Junk's center point) is inside the beam. If you're curious to see how this
is built, look at the worked example.

### Algorithm for `Game.resolveBeam`

The hard part to this phase is computing how long a junk has been inside the
beam. Here's my plain English process for this.

_Loop through all junk. For each junk, check if the Magpie beam contains its
location (`junk.physics`). If it does, add `delta` to junk's `beamTime`. If it
doesn't, reduce the junk's `beamTime` by `delta` instead (but don't let it go
below zero). If there are any junks inside the beam, see if any have been in
there longer than the catch time limit. If so, pick the one with the biggest
elapsed time, and return it. Otherwise return null._

If that description didn't work for you, here's pseudocode that has the same
idea, but in a code-like form:

```
best = null
for each junk in the level's junk list:
    if magpie's beam contains junk.physics:
        junk.beamTime = junk.beamTime + delta
    else:
        junk.beamTime = max(0, junk.beamTime - delta)
    if junk.beamTime > limit:
        if best is null:
            best = junk
        else if best.beamTime < junk.beamTime:
            best = junk
return best
```

### Spec

- Hold <Kbd>Space</Kbd> to turn the beam on; let go to turn it off
- The beam is a triangle with its point at the Magpie's center, opening out the
  back of the ship: the opposite way from forward thrust (down, when the ship
  faces up). It's `Magpie.BEAM_HEIGHT` long and `Magpie.BEAM_WIDTH` wide at the
  open end.
- Drawn with alpha transparency so objects inside it are still visible; drawn
  before the ship so the ship is on top. I used `"#f5f37040"` - the `40` at the
  end gives it `40/255` opacity
- Catching: each junk instance tracks `beamTime`, how long it has been in the
  beam
  - In the beam: `beamTime` goes up by `delta`
  - Out of the beam: `beamTime` goes down by `delta`, but not below 0. So
    sweeping past junk doesn't catch it, but a wobbly aim isn't punished too
    much.
  - Caught when `beamTime` passes `Game.JUNK_CATCH_TIME_MS`
  - If more than one junk is in the beam, catch the one with the most `beamTime`
  - `resolveBeam` returns the caught junk or `null`; the given `Game.move` does
    the rest
- Image: hand sketch of `beamTime` over time. It rises in the beam, drains out
  of it, and there's a dashed line at `JUNK_CATCH_TIME_MS`.

### Done when

- The beam shows only while Space is held
- Junk held in the beam for about half a second vanishes (for now, caught junk
  just disappears; delivering it comes in the next homework)
- Catching all the junk shows "All clear!"
