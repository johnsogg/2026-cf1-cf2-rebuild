# Space Junk, Local Edition

This homework revisits the
[Space Junk homework](/homework/space-junk-game/description). The purpose of the
first one was to have you write code to a spec, rather than following your own
creative instincts.

The purpose of this evolution of the homework is to kick off the p5.js web
editor training wheels by working from a locally edited git repository. This
will be a different way of working, and you will likely find it uncomfortable.

In this homework, you will (1) port your earlier homework to be managed in a git
repository. You'll then (2) edit the code with a local editor, and (3) round out
the game with a little more code.

## Why work locally?

Writing code locally gives you access to a host of additional tooling beyond the
p5 web editor:

- Use your choice of editor (of which there are many options)
- Source control for easily creating save points
- ... and for collaborating with others
- Automated testing
- Automated code checking ("linting")
- Automated code formatting
- Access to the full capabilities of your computer beyond the browser
- Install and use 3rd party libraries easily with package managers
- Configure everything to work as you want

If you're just starting to code, most or all of this might not seem particularly
compelling. I get that, and my response is probably not super satisfying: you'll
learn to appreciate the added control these tools give you, and through them,
you'll learn a lot about how computers actually work.

Above, I mentioned several reasons to work locally, but for now we're only going
to add git into the mix. Testing, linting, and package management are not in
scope here. Of course, you can go the extra mile(s) if you want to start using
those things!

## Install an editor and a git client

You can install any code editor you want. I recommend
[VS Code](https://code.visualstudio.com/), though it is laden with AI that will
want to do your homework for you. Find a way to turn all that off.

You'll also need a git client. There are many, but for consistency I'll
recommend [GitHub Desktop](https://code.visualstudio.com/). I don't personally
use it aside from showing students how to use it - I use the command line `git`
client. You will need to sign in to your GitHub account with this in order to
see your repositories.

### Create a new git repository

The first step is to create the landing spot for your code. There are many ways
to do this, but I'll show you a straightforward way that I use myself. Put
simply, use the GitHub UI to create an empty repository, then clone it and put
your files into it.

<Callout intent="note">
  There are many ways to use `git`, and the GitHub service is just one of them.
  GitLab and BitBucket are two popular alternatives, and there are others. These
  examples use GitHub because that is the most ubiquitous. If you want to use
  something else, go for it.
</Callout>

Once you have a GitHub account, create a new repository on the main screen using
the plus icon then choosing "New Repository":

### Add your Space Junk files to the local repository

This part is actually straightforward once you get into it. Open your first
Space Junk homework in the p5 web editor, and use `File > Download` to save a
zip file containing all of your files. Open the zip file, and you'll see all
your files: `sketch.js`, `magpie.js`, and so on. You'll also see all the files
you didn't write, like the `p5.js` bundle, and the `index.html` file that you
edited but didn't create. Here's what it looks like on my computer:

<ZoomImage
  src={localFiles}
  width={600}
  alt="Files unpacked from the p5 web editor"
/>

Now that you have the files somewhere on your disk (Downloads?) you can copy
those over to your fresh clone of your new repo.

Inside your editor, all you need to do is open the folder that contains your
repo (the one that you tattooed to your mind). Then, drag files from your file
explorer into the editor:

<ZoomImage
  src={localFilesCopy}
  width={800}
  alt="Copy Space Junk files into your editor"
/>

That should simply copy the files into the directory that your editor is working
from. From here you can go back to your git client and see that it sees that
you've added a bunch of files. GitHub Desktop now looks like this:

<ZoomImage
  src={githubWithFiles}
  width={800}
  alt="GitHub Desktop shows new files"
/>

At this point, you can commit and push these changes. Just add a Summary (bottom
left), and then press the "Commit N files to main" down below. This creates a
local save point that you can return to later. But you're not done yet - you
need to send these changes up to GitHub's server also. To do this, use the
'Publish branch' at the top right.

This will spin for a few seconds, then it will look pretty empty again. This is
good, because this screen is showing you differences - any edits that you've
made that haven't been committed. And we've committed everything, so it rightly
shows nothing.

If you go to the GitHub web page in your browser, you'll see this commit appears
in the web app. This might help you feel better that you've done something
useful.
