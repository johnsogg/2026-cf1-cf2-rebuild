# Syntax

You've encountered syntax your whole life, but might not have stopped to think
about it. In written natural languages like English, we build up words from
letters - lines, dots, curves, all put together in just the right way so you can
tell 'd' and 'b' and 'i' and 'j' apart. Further, those words are put together
into sentences, and the order you write them can be grammatically correct (or
not).

> This sentence is grammatically correct.

versus:

> Sentence correct this grammatically is.

The first one fits the language's grammatical conventions but the second one
doesn't. And if you've ever played
[Mad Libs](https://en.wikipedia.org/wiki/Mad_Libs) you know that even a
grammatically correct sentence can still be nonsense. Here's one:

> The NOUN hit the NOUN.

If you pick any two arbitrary nouns (telescope, banana), the results are usually
silly and fun, and since it is understood that you're not trying to communicate,
there's no problem. It is just a game.

> _The banana hit the telescope._ Or, _The telescope hit the banana._

But if what you're trying to do is convey meaning, grammar gives you a framework
for conveying very different information.

> _The ball hit the boy._ Or, _The boy hit the ball._

In the first case, the boy is possibly injured; in the second, the ball is now
flying through the air. Same syntactic structure, very different semantics.

## Syntax in Code

This syntax discussion is super important when it comes to code, so I wanted to
ground it in something readers already understand. If a person misspeaks and
says something grammatically incorrect ("Ow! Hammer... finger!") we can still
engage our brains and understand what the speaker is trying to convey. Grammar
helps us out, but doesn't guarantee anything, and often gets in the way.

Programming languages have their own grammars, just like natural languages. But
unlike natural languages, coding language must make unambiguous sense to a
computer, so programs must follow the grammar, or the computer won't be able to
proceed.

So, it is crucially important that programs fit into the language's grammar.
We've already seen some Javascript from the previous chapter, maybe we can start
our sytax discussion with what we've already seen.

This is an example of an _expression_. There are lots of different kinds of
expressions - there are expressions for doing arithmetic, calling functions
(we'll see this soon), and just about everything else the language lets you say.
An expression is just a passage of code that can evaluate to something. In this
case, the expression `foo = 'hello'` evaluates to the value `'hello'`.

Many expressions have a certain order for doing things, and the above sequence
follows that order. When you write a line of code, JavaScript scans it for clues
about what it should do with it. In this case, it sees

```
<thing-on-left> <equals-sign> <thing-on-right>
```

... which matches the syntax for an assignment expression.

**Equals sign.** The `=` character is doing a lot of work here. Now that JS
knows this is an assignment, it has to do something with the left and right
sides.

{/* prettier-ignore-start */}

**Expression.** The next step is to _evaluate_ the right hand side. It always
does this before it does anything with the left hand side. In this case, the
right hand side is simply `'hello'`, which is also known as a 
<Term>string</Term>&nbsp;<Term>literal</Term>. We'll soon see that the
right-hand side can be complicated, but it always resolves down to a single value.

{/* prettier-ignore-end */}

**Variable.** The last step in an assignment is to identify the variable that
the value will be assigned into. In this case, it is a variable named `foo`. We
haven't looked at any other kinds of landing spots yet, but they exist (e.g.
object properties, list elements). After this assignment operation, the variable
`foo` contains the value `"hello"`.

## Anatomy: Mutable Variable Declaration

We just saw how we can assign to an existing variable. But where do they come
from? You need to _declare_ them first with a name. If you want to make a
variable that can change over time, you don't need to give it an initial value.
Here's how you'd do that.

This combines the ideas from the assignment operation from earlier and the
variable declaration for `nickName`. But in this case we're both _declaring_ and
_assigning_ in a single line of code. This is called an _initialzer_. If you're
making a constant like `realName`, you have to give your variable a value now
because the language won't let you change it later.
