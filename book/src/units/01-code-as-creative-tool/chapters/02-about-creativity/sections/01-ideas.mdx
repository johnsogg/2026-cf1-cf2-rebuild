# Care and Feeding of Ideas

Ideas are wonderful things. They let you imagine a little alternate universe
where things are like _that_, instead of like _this_. But where do they come
from? How can you recognize an idea as something to cultivate, iterate,
transform? Do they grow up and have lives of their own? Can ideas have babies?

Ideas are the basis of all progress, so it pays to be able to discern the good
from the bad. But how? Lots of ways, and depending on the context, some
approaches will serve you better than others.

Writing code can be a good way to think through many ideas. It takes skill to
write the code yourself, which is what this whole book is about. Of course, you
don't need to be a software engineer to vibe code an idea with AI, though you'll
get better results if you understand how computers and code work.

## Sketches

In this book we use a Javascript library called p5.js to make simple interactive
'sketches'. The term 'sketch' is fitting, since the library is there to explore
ideas in a quick, rough, and expendable way, just like a paper sketch. The p5
sketches and similar little bits of code are good for practice, thinking,
testing out ideas.

You would not build a house without first making a blueprint, and you'd be nuts
to get that far without making (paper) sketches of different ideas. They give
your mind an external memory, and let you talk it over with other people, who
might get their own ideas based on what they see. (So yeah, ideas can have
babies!)

But thinking through ideas by writing "sketches" in code is different than it is
in most other domains because of the nature of the medium. A vague idea hacked
out in code can appear very similar to a concise, well-executed algorithm in
code. The medium for both rough thinking, exploration and precise implementation
is the same. The intent, purpose, outcomes, longevity are different.

## Ideas Are Cheap

> "That's a great idea!"

It is nice to hear somebody say that in response to whatever you just said. But
(and I'm not trying to be a downer here) simply having an idea is relatively
easy. If you've ever been in a brainstorming session, you probably know that the
hard part is sussing out the good ideas from the others. Defining "good" is
elusive enough; convincing others that the idea is good is even trickier.

Code gives you a way to explore an idea to see what's there and make an argument
for or against an idea's fitness. A skilled developer can turn an idea into a
prototype. One you start being able to make a point with code, it might become
your default way to express ideas. But in order to get there, you need to build
mastery.
